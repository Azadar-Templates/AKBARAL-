browser issued **zero** `/api/*` requests. A visitor saw only the statically
rendered header/footer — no landing, no sign-up, no dashboard, no MASTER.
curl-based checks could not see this because the API tier was healthy.

Fixed by restoring the local hosts to the allowlist. Locked in by
`src/app/mission-isolation.test.ts`.

## 22. What was fixed this session

1. **The entire client application was dead in a real browser** — `next.config.mjs`
   `allowedDevOrigins` dropped `localhost`/`127.0.0.1`, so Next blocked its own
   dev resources, hydration never completed, and the `afterInteractive` script
   that loads `public/app.js` was never inserted. Nothing beyond the static
   header/footer rendered and the browser never called the API. Fixed; 22/22
   browser checks now pass. (`next.config.mjs`)
2. **ZA141251SA isolation breach (critical)** — `/api/boss/*` reads the PRIVATE
   mission database and was mounted unconditionally on the PUBLIC AKBARAL! API,
   with a guard that failed OPEN when no dashboard token was configured. Proven
   live before the fix: an anonymous `GET http://…:3000/api/boss/overview`
   returned the whole private fleet, treasury and audit totals. Now the route is
   mounted only with an explicit opt-in **and** a ≥32-char token, and the guard
   itself fails closed with a constant-time comparison. Re-verified: all
   `/api/boss/*` paths answer 404 on the public tier while the private mission
   server on :4200 still serves them to the authenticated owner.
   (`src/app.ts`, `src/routes/boss-dashboard.ts`)
3. **Rate-limit bypass via header spoofing** — the limiter keyed on `req.ip`,
   which Express derives from `X-Forwarded-For` whenever `TRUST_PROXY` is set
   (it is, because the Next tier proxies the API). Any caller could rotate the
   header and never be throttled — 330 consecutive requests were accepted. The
   limiter now discards forwarded values whenever the raw chain is longer than
   the configured trusted hop count and keys on the socket address instead.
   (`src/server/middleware/rate-limit.ts`)
4. **Sessions died on every dev restart** — `npm run dev` minted a fresh
   `SESSION_SECRET` per process. Dev and prod now share
   `scripts/lib/session-secret.mjs` (persisted at `<DATA_DIR>/.session-secret`,
   0600, never logged). Verified across two restarts.
   (`scripts/start-dev.mjs`, `scripts/start-prod.mjs`, `scripts/lib/session-secret.mjs`)
5. **Disabled OAuth buttons explained only by a tooltip** — a `title` on a
   disabled control is invisible on touch and to a quick glance. The auth card
   now states it in text. (`public/app.js`, asset version bumped to
   `akbaral-lux-19`)
6. **Two stale tests made `npm test` red on a clean checkout** —
   `stackhost-deploy.test.ts` still demanded a `ghcr.io` image after the merged
   deployment switched to its Docker Hub mirror; `data-dir.test.ts` asserted
   `DATA_DIR` inside `start-prod.mjs` after the shared-secret extraction. Both
   updated to assert the real contract (and `data-dir.test.ts` now also pins the
   dev/prod parity from fix #4).
7. **New tests and tooling** — `src/app/mission-isolation.test.ts` (4 tests
   locking fixes #1, #2 and #4), `scripts/testing/browser-auth-journey.mjs`
   (22-check real-Chromium journey), `scripts/testing/mission-dashboard-check.mjs`
   (7-check private dashboard journey), `scripts/testing/browser-probe.mjs`.
8. **Mission system brought up for real** — `mission:init` (34 migrations, 123
   tables, owner provisioned, identity lockdown enforced) and
   `mission:sync-registry` (4,001 mission identities, zero opening cash).
